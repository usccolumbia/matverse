# Searchable MatVerse UI

The public directory is at https://usccolumbia.github.io/matverse/. The generated root `index.html` is self-contained and can also be opened directly from disk. It does not fetch catalog data, fonts or scripts from an external service.

Source files:

- `index.template.html`: semantic document and controls.
- `styles.css`: responsive teal/lime directory design inspired by the provided screenshot.
- `app.js`: search, combined filters, sorting, dataset details, resource and complete collection-entry search, URL state and CSV/JSON export.

After editing catalog data or UI sources:

```sh
python3 scripts/build_catalog.py
python3 scripts/build_sources.py
python3 scripts/build_site.py
node --test tests/ui.test.cjs
```

CI checks that all generated files match their sources. The root `.nojekyll` file permits direct static publication from the `main` branch on GitHub Pages. Catalog data remains authoritative in `data/datasets.json` and `data/resources.json`; the HTML embeds a generated copy. `data/ui_manifest.json` records the source and output hashes.

The API / Agent-ready view (`?view=apis`) embeds `data/api_sources.json`. Search combines with interface (`api_kind`) and authentication (`api_auth`) filters; CSV/JSON exports retain access notes, verification status, limits and evidence. API cards can open related dataset releases. The OPTIMADE guide and complete JARVIS audit are generated by `scripts/catalog_supplements.py`; routes do not add independent dataset counts. Global search also exposes API matches.

The Source entries view embeds all link occurrences from `research/collection_*.json` inventories, excluding the separate additions files. `scripts/collection_inventory.py` supplies the common importer for the site and source-index generator. `data/collection_entries.json` and `docs/collection-coverage.md` are generated by `build_sources.py`. Repeated URLs retain their original collection and section context. Collection and scope filters combine with search; `?view=sources&collection=blaiszik` opens a specific inventory. Imported entries are discovery leads, distinct from the ranked datasets and curated portal cards.

Search uses all words (AND), ignores case and dash variants, and supports quoted phrases. Filters combine with search. Numeric sort keeps unknown sizes last; the initial sort groups categories and orders each by descending size. The types tab groups the selected count unit rather than asserting that every row has the same kind of data. Exact counted units remain visible.

Search/filter state can be shared via URL parameters; `#dataset-id` opens a release's source details. Press `/` to focus search. All primary source links open separately. “Terms documented” includes restrictive or commercial terms, and must not be interpreted as an open license.

Search normalizes the explicit superconductivity term family (superconductor/superconductors, superconductivity, superconducting, superconductive and SuperCon) and the critical-temperature/Tc alias. Original text remains searchable too. A query overview reports matches across datasets, curated portals and complete source inventories, independently of the current view's filters. Opening a result group clears its view-specific filters and preserves the query; source-entry searches preview matching dataset names, so a collection missing a 3DSC link does not hide the catalog's 3DSC records.

Search performance: an in-memory index is prepared once for the immutable bundled catalog; query tokens and the locale collator are reused. All matches remain on one page (no pagination). Dataset evidence panels are constructed when opened, and fast typing is coalesced with a 100 ms delay; Enter applies immediately. CSV/JSON export applies the latest query and includes every matching result. Run `node scripts/benchmark_search.cjs` from the repository root for a search-only benchmark; browser rendering and the typing delay are outside that measurement.
