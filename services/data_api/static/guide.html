Data you can reproduce.

Retrieve a named property table, or prepare a filtered table with matching crystal structures.

Install the Python client

pip install materialsatlas
# Optional DataFrames and pymatgen objects:
pip install 'materialsatlas[data,structures]'

While the first PyPI publication is pending, install the tested wheel with pip install https://materialsatlas.org/data-downloads/packages/materialsatlas-0.1.0-py3-none-any.whl.

from materialsatlas import get_available_datasets, download_dataset, load_dataset

print(get_available_datasets())
path = download_dataset("band_gap")
df = load_dataset("curie_temperature")  # requires the data extra

Large tables may not fit comfortably in a DataFrame. Use Parquet batches or DuckDB for those tables.

Filter properties and include CIFs

from materialsatlas import MaterialsAtlas

with MaterialsAtlas() as atlas:
    job = atlas.export(
        property="band_gap",
        property_source="materials-project",
        elements=["Li", "O"],
        include_cifs=True,
        format="parquet",
    )
    print(job.id)
    files = job.download("./materials-data")

    # CIFs for structures associated with OQMD:
    files = atlas.download_cifs(
        structure_source="oqmd", directory="./oqmd-data"
    )

Exports run in a persistent queue and normally expire after seven days. Resume one with atlas.job(export_id).download(directory). Downloads verify SHA-256 hashes and support resumption; archives are not extracted automatically. Large exports may require narrower filters to stay within the service limits.

Sources mean different things

  • property_source: the provider reporting a property value.
  • structure_source: membership in a database, as reported by MateriaViva.
  • origin_source: the recorded origin of the representative CIF.
  • origin_open=True: require coordinates marked as openly sourced by the publisher.

A structure associated with Materials Project may have its representative CIF supplied by another source. Multiple property values and methods are retained separately. Public property exports include only rows labelled open by the publisher; this label does not replace the record's original terms. Cite MateriaViva and the original providers.

ML predictions are explicit

with MaterialsAtlas() as atlas:
    print([task["name"] for task in atlas.predictions()])
    path = atlas.download_prediction("lattice_thermal_conductivity__gga")

Predictions are estimates, not new experimental measurements or DFT calculations. Each task retains its model metadata. Curves are mirrored for preservation but are not served by this first API release.

OPTIMADE structure discovery

with MaterialsAtlas() as atlas:
    for entry in atlas.optimade('elements HAS ALL "Li", "O" AND nelements=2'):
        print(entry["id"], entry["attributes"]["chemical_formula_reduced"])

    record = next(atlas.iter_structures(elements=["Si"], page_size=1))
    structure = atlas.get_structure(record["material_id"])  # pymatgen extra

The endpoint is /optimade/v1/structures. It normalizes the stored CIF cell and coordinates. Some source metadata describes a different cell, so normalized site counts can differ. Unsupported CIFs are omitted from OPTIMADE and remain available through raw downloads. Nested-property and correlated-list filters are not supported; unsupported filters return an error.

OPTIMADE serves the active release. Use MaterialsAtlas(release="full-revision") for reproducible source-property and raw-CIF retrieval. The exact resolved revision and checksums accompany every generated export.

Direct HTTP access

curl https://materialsatlas.org/api/data/v1/properties
curl -X POST https://materialsatlas.org/api/data/v1/exports \
  -H 'Content-Type: application/json' \
  -d '{"property":"band_gap","property_source":"materials-project","include_cifs":true,"limit":100}'

Poll /api/data/v1/exports/{id} for download links. The interactive API documentation describes all filters and response schemas.
